# Робота над Mana Tape

Перед зміною поведінки прочитайте README.md, docs/DESIGN.md і docs/ARCHITECTURE.md.

- Проєкти OMP зовнішні. Код не повинен залежати від конкретного користувача, хоста, набору ролей або каталогу встановлення. Особливості інсталяції — у приватній конфігурації.
- Ніколи не зупиняйте й не перезапускайте OMP або його воркери. За потреби перезапускається лише Mana Tape.
- Перевіряйте записи лише на одноразових fixtures. Не очищуйте відкриту вкладку користувача з чернетками.
- Зберігайте ревізії, чернетки, коментарі YAML, резервні копії та відновлення транзакцій. Не обходьте конфлікти.
- Невідоме, застаріле, FREE та вичерпане — різні стани. Не вигадуйте даних або успішних перевірок. Немає ціни — не означає FREE.
- Не додавайте ключів, токенів, auth DB, native конфігурацій, приватних журналів чи резервних копій у Git. Перевіряйте staged-файли.
- Імена `forge` — сумісні внутрішні ідентифікатори. Не перейменовуйте їх без міграції.
- Використовуйте наявний стек. Нові залежності та узагальнення додавайте лише за конкретної потреби.
- Після змін запускайте `make test check`. Для інтеграції — її окремі тести. Мережеві inference-перевірки не входять у тести за замовчуванням.
- Після змін UI перевірте світлу/темну тему, 1440 або 1920, 1280, 390 і 320px; довгі/невідомі назви, порожній пошук, клавіатуру, drag/tap та Undo. Скріншот не доводить роботу подій. Записуйте фактично виконані перевірки.
- Зберігайте граматику CUT / CUTS / EDITION, читабельність, reduced motion, фокус і прокручування. Фонове оновлення не має анімувати монтаж.
- Не змінюйте видимість GitHub без явного запиту власника. Ліцензію основного проєкту має обрати власник.
