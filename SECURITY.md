# Безпека

Mana Tape призначений для одного довіреного власника. Сервер слухає лише `127.0.0.1`; це не багатокористувацький або публічний вебсервіс. Без `origin` доступ мають локальні процеси цього комп’ютера. Не використовуйте такий режим на недовіреній спільній машині.

Процеси того самого користувача ОС мають доступ у будь-якому режимі: вони можуть прочитати `local-token` і так само напряму змінити YAML OMP. `local-token` захищає від вебсторінок у браузері та від інших облікових записів ОС, а не від програм самого власника.

Для віддаленого доступу використовуйте SSH-проксі або приватний Tailscale Serve з точно заданими `origin` та `owner`. Не публікуйте сервер у відкритий інтернет. Заголовок Tailscale-ідентичності має надходити лише від довіреного локального проксі. На Linux сервер перевіряє власника TCP-з’єднання через `/proc/net/tcp`: заголовки Tailscale приймаються лише від root (`tailscaled`) або від користувача, під яким працює Mana Tape; інший обліковий запис ОС отримує 403. На macOS та інших системах без `/proc` власника з’єднання перевірити неможливо: інший локальний обліковий запис може видати себе за Tailscale-проксі. Там використовуйте режим `origin` лише на комп’ютері без недовірених облікових записів, інакше — SSH-проксі.

Перевіряються Host, Origin, cross-site запити, Content-Type і CSRF. Адміністративний `local-token` зберігається з правами 0600, змінюється після запуску сервера і не передається браузеру. SSH-проксі додає його на серверному боці. Після перезапуску Mana Tape перезапустіть проксі.

Проєкти однієї інсталяції мають одного власника і спільний доступ. Каталоги стану містять конфігураційні резервні копії й потребують такого самого захисту, як ключі OMP. Ключі не входять у відповідь `/api/state`; особисті конфігурації, журнали й стан не належать Git.

Ключ, введений у панелі, зберігається окремим файлом `<agent>/forge-keys/<провайдер>-<випадковий суфікс>` (0600) і підключається через `!cat`. Після заміни ключа, переходу на `auth: none`, видалення провайдера чи завершення строку дії файл, на який більше не посилається жоден провайдер, видаляється; файли поза `forge-keys` панель не чіпає. Резервні копії `models.yml` можуть посилатися на вже видалений файл ключа: після ручного відновлення введіть ключ заново. Форма «+ Провайдер» лише створює: запит із `mode: create` і вже зайнятим ID сервер відхиляє (409 `provider-exists`), тож новий провайдер не може непомітно замінити адресу, ключ чи список моделей наявного; зміна наявного — тільки через «Підключення…».

Помилки сервера пишуться у stderr служби лише як тип винятку, errno й місце в коді — без тексту повідомлення, шляхів, тіл запитів, ключів чи відповідей моделей.

Повідомлення про вразливість надсилайте через [приватну форму GitHub](https://github.com/bramms/ManaTape/security/advisories/new) — Security → Report a vulnerability. Не публікуйте секрети чи деталі вразливості у відкритому issue. Для звичайних помилок без чутливих даних використовуйте Issues.
