# OpenCode Free — необов’язковий компонент

Локальний HTTP-міст і native-розширення OMP реєструють окремого провайдера `opencode-free`. Основна панель Mana Tape працює без цього компонента. Звичайні `opencode-go` / `opencode` підключення не змінюються.

## Як це працює

`OMP → розширення → 127.0.0.1:8765/free/v1 → підтверджений Zen або Go маршрут`.

Каталог перевіряє живі ID й докази нульової ціни. Невідомі ціни, платні записи, deprecated та нечатові маршрути відхиляються. Вибір Zen/Go зберігається для точного ID; при помилці міст не перемикає його на іншу модель чи платний маршрут. Власний fallback-ланцюжок OMP при цьому залишається відповідальністю користувача.

Go і Zen — різні адреси з різними наборами маршрутів. Наявність підписки Go не доводить доступність конкретного `*-free` на Go endpoint. Використовується той маршрут, який підтверджений каталогом. Не підтримуйте статичний список «завжди безкоштовних» моделей.

## Встановлення

Потрібні Python 3.11+, OMP і власний ключ Zen/Go. Міст не потребує встановленого OpenCode CLI. Приклад копіює лише компонент у незалежний каталог:

```sh
mkdir -p ~/.local/share/omp-free-bridge
cp -R integrations/opencode-free/. ~/.local/share/omp-free-bridge/
cd ~/.local/share/omp-free-bridge
python3 bridge.py login
python3 bridge.py catalog
```

`login` запитує ключ приховано й записує локально з правами 0600, не викликаючи inference. Ключ, токен, runtime й кеш лежать у `~/.config/omp-free-bridge`. Не додавайте їх до Git і не використовуйте console `st-` token як API-ключ.

Запуск:

```sh
python3 bridge.py serve --port 8765 --compat-opencode
```

`--compat-opencode` явно вмикає адаптацію форми запиту: протокольну ідентичність, сесію та набір описів інструментів. Спостережувана відсутність потрібного набору інструментів може призводити до 429; сам код 429 не доводить вичерпання квоти. Адаптер не виконує доповнені інструменти сам і не обходить ліміти. Це неофіційна сумісність, яка залежить від змін upstream; враховуйте правила свого облікового запису. Без прапорця поведінка відрізняється, успіх виклику не гарантується.

Підключіть розширення до потрібного agent-каталогу:

```sh
mkdir -p ~/.omp/agent/extensions
ln -s ~/.local/share/omp-free-bridge/extension.mjs ~/.omp/agent/extensions/opencode-free.js
```

Саме `.js` потрібен для автоматичного discovery OMP; джерело розширення лишається `.mjs`. Для іншого agent-каталогу змініть шлях. Mana Tape при оновленні каталогу явно завантажує встановлений `opencode-free.js`. Міст мусить працювати також під час реальних викликів OMP.

## Автозапуск і підтримка

На Linux готовий unit — `deploy/omp-free-bridge.service`:

```sh
mkdir -p ~/.config/systemd/user
cp deploy/omp-free-bridge.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now omp-free-bridge.service
python3 bridge.py doctor
```

Systemd запускає процес і відновлює його після збою. Для старту без входу потрібен linger користувача. На macOS скористайтеся launchd-прикладом основного проєкту, задавши іншу назву служби та аргументи `python3 /absolute/path/bridge.py serve --port 8765 --compat-opencode`.

Міст не підтримується активною сесією Codex і не залежить від неї. Власник інсталяції оновлює код, ключі та перевіряє зміни upstream. Supervisor відновлює процес, але не виправляє змінений протокол або відкликаний ключ.

`doctor` читає локальний стан без inference. `probe --model EXACT_ID --lane zen` або `probe --all` виконує **реальні запити** лише до allowlist; запускайте їх свідомо. Обмеження квоти й доступу провайдера діють і для FREE. Тести в `tests/` ізольовані й не використовують справжній ключ.

Для вимкнення зупиніть службу та видаліть лише своє посилання `extensions/opencode-free.js`. Перед наступним запуском OMP приберіть неактивні маршрути з його профілів. Не видаляйте інші розширення або облікові записи.
