# Архітектура

Mana Tape — вебпанель одного власника. Python `ThreadingHTTPServer` обслуговує статичні файли та JSON, `ruamel.yaml` зберігає YAML-коментарі й структуру. Фронтенд без збірки та фреймворку. Для роботи UI не потрібні база даних, хмара, SSH чи OpenCode Free.

Продуктові й візуальні вимоги — у [DESIGN](DESIGN.md), правила підтримки — у [MAINTENANCE](MAINTENANCE.md). Цей документ описує межі реалізації та карту коду; приватні шляхи інсталяції задаються через [конфігурацію](CONFIGURATION.md).

`index.html` підключає CSS у порядку `style.css → theme.css → tape.css → operator.css`. Останній файл уточнює попередні шари; не додавайте новий шар лише для обходу наявного каскаду. Основні container queries прив’язані до контейнера `forge`, тому ширина робочої поверхні важлива поряд із шириною viewport. Після зміни каскаду перевіряйте обчислені стилі та фактичний вигляд у двох темах і на потрібних розмірах.

## Проєкти й API

Для кожного запису конфігурації створюється власний `Forge`: проєкт, agent, стан, режимні метадані, статистика. `?project=id` вибирає об’єкт для конкретного запиту. Глобального змінного «активного проєкту» на сервері немає. Перший проєкт обслуговує старі URL без параметра.

Доступ, адміністративний токен і CSRF спільні для інсталяції одного власника. Проєкти зі спільним agent поділяють блокування запису реєстру й метадані провайдерів. `state/registries/<hash agent path>/providers.json` — їхнє єдине джерело; копія в проєктному `state.json` зберігається для сумісності. При першій міграції неоднозначні старі метадані з різними строками дії блокують запуск, а не вибираються за порядком проєктів. Це не багатокористувацькі дозволи. Сервер не приймає шляхи до файлів від браузера.

Читання: `GET /api/state`. Запис: `POST /api/profile-preview`, `/api/profile`, `/api/profile-action`, `/api/free-pools`, `/api/provider`, `/api/favorites`, `/api/refresh`. POST потребує JSON, CSRF і доступу до інсталяції. Відповіді каталогу містять лише дозволені поля моделей; ключі не передаються.

Помилка — JSON `{error}`; для станів, які інтерфейс має розпізнати, додається `code`: `mode-conflict` зі списком `profiles` (файл змінено поза Mana Tape), `mode-recovery` зі списком `files` (незавершена транзакція режимів), `symlink` (запис через символьне посилання). `/api/state` також повертає `modeConflicts`, `modeOrphans` (запис режиму без файла), `modeRecovery` (`null` або `{error, files}`) і `profileWarnings` (пресети, які не вдалося прочитати; решта проєкту працює).

## HTTP і кеш

Сервер працює за HTTP/1.1 keep-alive; кожна відповідь має `Content-Length`. JSON і текстові статичні файли стискаються gzip, якщо клієнт надсилає `Accept-Encoding: gzip`. Статичні файли мають ETag за вмістом і відповідають 304 на `If-None-Match`. Віддаючи `index.html`, сервер замінює `?v=` кожного локального файла в `src`/`href` версією за його вмістом (12 знаків SHA-256) і додає її там, де версії не було. Лише URL із версією, що збігається з поточним вмістом, має `Cache-Control: public, max-age=31536000, immutable`; оболонка, `sw.js`, URL без версії чи з іншою версією — `no-cache` з ETag. Нова версія файла завжди отримує новий URL, тож вручну піднімати `?v=` для кешу браузера не потрібно; список `sw.js` і назва його кешу стосуються лише офлайн-оболонки.

`/api/state` лишається `no-store`, але має слабкий ETag; серверний час `tariff.at` у ньому не враховується, як і в порівнянні знімків у браузері. Браузер сам не надсилає `If-None-Match` для `no-store`: клієнт, який хоче 304 без тіла, передає останній ETag явно.

Розібраний YAML для читання кешується за точним вмістом файла (SHA-256), а не за часом зміни, тож зовнішня правка ніколи не читається зі старого запису. Ці спільні дані лише для читання: спроба змінити їх дає `TypeError`, а `copy.deepcopy` повертає звичайну копію. Запис завжди перечитує round-trip YAML, щоб зберегти коментарі. Розібраний кеш SQLite каталогу OMP використовується до 30 с, доки `models.db` і його WAL мають той самий stat; оновлення каталогу читає їх напряму. Frontmatter агентів кешується так само за вмістом.

## Збереження

Конфігурація OMP зовнішня: `.omp/config.yml` і `.omp/presets/*.yml`. Standard — база; UI редагує об’єднані профілі, сервер записує мінімальні перевизначення та лишає інші поля незмінними. Дозволені лише підтримувані шляхи полів. Штатні ролі передаються через `builtinRoles` як метадані відображення; їх немає у робочих значеннях профілю, доки користувач не призначить модель. Додаткові ролі й агенти беруться з конфігурації. Сервер дозволяє призначати та скидати штатні ролі, навіть якщо вони відсутні у YAML; довільні нові ролі через API не створюються. Тип моделі перевіряється на відомих даних каталогу.

Копіювання й перейменування нормалізують лише нове ім’я: обрізають пробіли по краях, переводять у нижній регістр і замінюють внутрішні пробіли дефісами. Далі діє нативне правило ASCII ID до 64 символів. Відповідь повертає канонічне `name`, яке UI використовує для вибору профілю, чернетки й Undo. Колізії відхиляються без перезапису. Пошук наявного файла лишається строгим; Standard не можна перейменувати чи видалити.

Послідовність: валідація → порівняння ревізії → резервна копія → тимчасовий файл → flush/fsync → атомарна заміна. Ревізія враховує базу, preset і режимні метадані. Застарілий запис повертає 409. Symlink замість конфігурації не підтримується. Це стосується й `models.yml`: запис через посилання відхиляється з `symlink`, посилання не замінюється звичайним файлом, а провайдер із минулим строком лишається з `expiryReason: symlink`. Зовнішній редактор, що ігнорує блокування, теоретично може записати файл у короткому проміжку між останньою перевіркою й заміною; абсолютної міжпроцесної гарантії немає.

`profile-modes.json` зберігає логічний профіль, налаштування DeepSeek, пули й застосовану проєкцію. Preview прив’язаний до конкретних змін і каталогу: сервер не підміняє рішення непомітно під час Save.

`profile-mode-transaction.json` — журнал операцій над профілями: збереження режиму й пулів, копіювання, відновлення, перейменування, видалення та прийняття файла. Порядок: журнал → native-файли → метадані → видалення журналу. Новий файл (копія, нове ім’я) створюється ексклюзивно й ніколи не замінює файл, що з’явився тим часом. Поки журнал існує, кожна дія запису через API (профілі, пули, провайдери, обрані) спершу завершує або відкочує транзакцію, а preview чекає на це так само; журнал ніколи не перезаписується. Фонове оновлення каталогу, лімітів і строків провайдерів профілів не торкається й не блокується. Стан файлів порівнюється як точні байти, тож CRLF не заважає відновленню. Якщо всі файли досягли нового стану, транзакція завершується; інакше файли в новому стані повертаються до попереднього. Файл, змінений іззовні під час запису, не чіпається: журнал лишається, а запис відхиляється з `mode-recovery`, доки власник не прийме цей файл; повний журнал тоді зберігається в резервних копіях. Невдале відновлення під час старту не зупиняє сервер: панель читається, запис заблоковано.

Зовнішня зміна файла з режимним записом — конфлікт. Конфлікт Standard або цільового профілю блокує запис із `mode-conflict`; інші змінені пресети лишаються байт-у-байт незмінними разом зі своїми записами, поки решта профілів зберігається. Дія `adopt` у `/api/profile-action` з актуальною ревізією приймає поточний файл: файл не переписується, він стає логічним профілем із DeepSeek ON і збереженими замінами, а попередня логічна версія лишається для Restore. Похідні профілі перекомпільовуються через той самий журнал. Якщо файла більше немає, `adopt` прибирає запис режиму, зберігши його копію. Пресет, який не вдалося прочитати, пропускається з `profileWarnings` і не зупиняє знімок, перевірку строків чи оновлення каталогу.

`mana-pool/free-good` і `mana-pool/free-fast` існують лише в логічних метаданих. Компілятор розгортає їх у native маршрути для OMP. Збереження пулів перевіряє всі залежні профілі перед записом. Кількість CUTS у FREE-пулах не обмежена. Пул займає одну позицію логічної доріжки; його розгортання не обмежує кількість native маршрутів. Перевірки безкоштовності, дублікатів, thinking, сумісності ролей і конфліктів зберігаються. Рівні thinking беруться зі списку моделі або з `thinking.efforts` (форма розширень OMP); каталог віддає їх списком. Порожній чи відсутній список означає «невідомо» і не перевіряється — так само в пулах, компіляторі й браузері. Ролі OMP без thinking (`judge`, `web`, `image` тощо) отримують заміни без суфікса effort, а порожній власний список агента лишається порожнім і в режимі без DeepSeek.

Секція «Агенти» об’єднує `agents` API (штатні та виявлені власні агенти) із записами `task.agentModelOverrides`. Власних агентів сервер знаходить під час кожного `GET /api/state`: розбирає лише YAML-frontmatter (`name`, `description`, `model`) у `.omp/agents/*.md` проєкту й `agents/*.md` каталогу агента OMP; пріоритет — проєкт, користувач, штатний. Файли лише читаються; некоректні пропускаються з нефатальним `agentWarnings`. Штатні й виявлені визначення — метадані API; відкриття й оновлення панелі не матеріалізують їх у YAML або режимних профілях. Сервер дозволяє призначити й скинути перевизначення штатного чи виявленого агента, якого ще немає у YAML. Інші імена приймаються лише якщо вже є в конфігурації. Перевизначення зниклого агента лишається видимим і його можна прибрати, зокрема зі Standard. Компілятор зберігає одиночне `@role` як посилання, навіть якщо роль використовує пул; розгортання ролі не повинно перетворювати успадкування на власний список агента. Семантика обох форм і копіювання резервів описана один раз у [USAGE](USAGE.md#агенти). Внутрішні ключі `vibe` залишаються сумісними ідентифікаторами UI та режимних метаданих і не обмежують набір агентів.

FREE потребує нульових цін input/output/cache та явної FREE-назви або перевіреного підтвердження провайдера. `VERIFIED_FREE_ROUTES` у `server.py` містить точний маршрут, endpoint і офіційне джерело; сервер передає `freeEvidence` інтерфейсу та компілятору. Це підтвердження не змінює ID, не дозволяє ненульових чи невідомих цін і не поширюється на інші моделі або сторонній endpoint. Для `nvidia/deepseek-ai/deepseek-v4.1-flash` джерело — [офіційна сторінка NVIDIA](https://build.nvidia.com/deepseek-ai/deepseek-v4.1-flash), перевірена 2026-09-26; безкоштовність endpoint не скасовує його ліміти.

## Браузер

`original` — останній відомий серверний стан, `profiles` — робочі значення профілів. Редагування змінює чернетку; Save надсилає зміни з її ревізією. Session storage тримає незбережені значення та вихідні ревізії цієї вкладки. Undo/Redo має обмежену локальну історію й не є серверним журналом. FREE-пули мають окремі чернетку, ревізію та Undo/Redo.

Чернетки й останній вигляд мають простір імен за канонічним шляхом проєкту. Навігація між проєктами створює новий контекст сторінки. Застарілі відповіді не змінюють новий проєкт. Теми, налаштування LCD і висота колекції — спільні в цьому браузері. Legacy-ключі `forge` збережені для сумісності; міграція старих чернеток дозволяється явно для одного проєкту.

Жест попередньо показує результат і фіксує одну дію при завершенні. Обробники ручок, перенесення CUT із колекції та зміни висоти лотка скасовують жест при Escape, pointer cancel/lost capture або втраті фокуса вікном; скасування resize повертає початкову висоту. Синтетичний клік після drag не запускає другу дію. Перетягування всередині доріжки переставляє CUT, між доріжками — копіює його зі thinking. Точний маршрут, уже наявний у цільовому ланцюжку, переміщується без дублювання. Семантика місць вставки й заміни описана у [DESIGN](DESIGN.md).

Вікно — дерево названих регіонів (`static/app.js`, «REGIONS»): верхня панель, пульт, лічильники, транспорт DeepSeek, пули й лотки, кожна доріжка ролі й кожен агент окремо, колекція CUTS, picker, модальне вікно, toast; Колекція й Історія мають власні блоки. Регіон — діапазон DOM між двома коментарями-маркерами разом із рядком HTML, з якого його зібрано. `render()` — єдина точка входу: збирає рядки й замінює лише регіони, чий рядок змінився; контейнер із тими самими дочірніми ключами лише оновлює атрибути свого відкривального тега. Незмінений DOM зберігає фокус, виділення, композицію IME, прокручування й відкриті `<details>`; для перебудованого регіону фокус, виділення, прокручування й меню відновлюються. Позначки HEALTH, ціль picker і палітри LCD — декорації поза рядками: вони накладаються на нові регіони, а зміна перемикача, профілю чи вимірів оновлює позначки в усьому вікні без перебудови. Пошук, HEALTH, toast і хвилинний тік тарифу оновлюють лише свої регіони.

Ререндер зберігає фокус, виділення у формах і прокручування; фонове опитування пропускається під час активного введення, жесту, picker, модального вікна чи збереження. Відповідь preview не змінює геометрію монтажу й не перезапускає появу відкритої панелі. Анімації реагують на зміну чернетки чи контексту, не на звичайний знімок квот, і враховують reduced motion. Service worker кешує лише оболонку; `/api/` ніколи не кешується. Статичний кеш не надає офлайн-доступу до приватного стану. Перший `/api/state` index.html починає через `<link rel=preload>` (знімок проєкту за замовчуванням; інший проєкт запитується вже з `app.js`). Фонове опитування надсилає `If-None-Match`; 304 — незмінений знімок, без розбору й без роботи з DOM. Жести пишуть геометрію безпосередньо в елементи, які її використовують, не частіше разу за кадр, а читання геометрії передує записам.

Пошук оновлює лише результати, зберігаючи активний input. Перевірка взаємодії повторюється після фонової відповіді; незавершений запис і застаріла відповідь не можуть повернути попередній стан. Для preview діє вужча межа: завершений вибір Thinking і меню перестановки мають отримувати готову проєкцію без закриття. Повторна дія з індексом CUT очікує актуальної проєкції. Похідні дані моделей (ціна, ключ пошуку, оцінка тестів, відфільтрована колекція CUTS) кешуються за версією знімка й каталогу (`dataVersion`) і значеннями фільтрів: новий знімок не зустрічає старих значень, тож ручної інвалідації немає. Решта похідних обчислень (diff, ключ preview) живе в межах одного render.

## Межі інтеграцій

Для `opencode-free` підтвердження зникнення бере локальний `catalog.json` установленого мосту (`OMP_FREE_HOME` або стандартний каталог мосту). Приймається лише повний непрострочений знімок, узгоджений із поточним результатом OMP. ID з `excluded` не вважаються видаленими; неповні чи застарілі дані не доводять зникнення. Перевіряються також попередні та налаштовані маршрути, щоб пропущене раніше зникнення не залишалося назавжди зі статусом `present`. Конфігурації й порядок CUTS при оновленні каталогу не змінюються.

Для `openrouter` і `kilo` OMP тримає вбудований список моделей, з якого відкликані FREE-маршрути не зникають. Тому під час оновлення панель читає їхні публічні списки моделей без ключа; для OpenRouter — з `output_modalities=all`, щоб embedding-, rerank- та інші не-чат моделі не виглядали зниклими. FREE-маршрут, який OMP ще показує, а публічний список не містить, отримує статус `missing`. Список є доказом, лише якщо містить хоча б один відомий FREE-маршрут провайдера та більшість його маршрутів з OMP. Мережева помилка чи непереконливий список зберігають попередній результат цієї перевірки. Повернення маршруту до списку знімає DELETED. Пули й профілі не змінюються: DELETED-учасники лишаються видимими, а вибір нових їх не пропонує.

OMP викликається для каталогу, лімітів і агрегатів, не для inference. Agent-каталог задається через `PI_CODING_AGENT_DIR`. Панель не управляє життєвим циклом OMP-воркерів. OpenCode Free працює в окремому процесі та має власний стан; його відсутність не зупиняє UI. Автоматичний supervisor — системна служба користувача, а не агент чи запущена сесія Codex.
