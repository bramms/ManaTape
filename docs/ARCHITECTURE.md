# Архітектура

Mana Tape — вебпанель одного власника. Python `ThreadingHTTPServer` обслуговує статичні файли та JSON, `ruamel.yaml` зберігає YAML-коментарі й структуру. Фронтенд без збірки та фреймворку. Для роботи UI не потрібні база даних, хмара, SSH чи OpenCode Free.

Продуктові й візуальні вимоги — у [DESIGN](DESIGN.md), правила підтримки — у [MAINTENANCE](MAINTENANCE.md). Цей документ описує межі реалізації та карту коду; приватні шляхи інсталяції задаються через [конфігурацію](CONFIGURATION.md).

## Карта репозиторію

| Частина | Відповідальність |
|---|---|
| `server.py` | Конфігурація інсталяції, проєкти, HTTP і доступ, адаптер YAML, ревізії, резервні копії, провайдери, журнал транзакцій |
| `profile_modes.py` | Чиста компіляція режимів, розгортання FREE-пулів, сумісність і тарифні вікна |
| `insights.py` | OMP usage/stats, нормалізація лімітів, оновлення публічних результатів тестів |
| `benchmark_sources.py`, `benchmarks.json`, `developer-benchmarks.json` | Адаптери джерел, початковий публічний зріз і вручну перевірені заяви розробників; правила у [BENCHMARKS](BENCHMARKS.md) |
| `static/app.js` | Чернетки, довільні ролі, монтаж, події, каталог та історія |
| `static/operator-core.js`, `static/evidence.js` | Чисті правила лімітів, FREE, перестановок, зіставлення результатів |
| `static/tape.js` | Undo/Redo, анімації без доступу до запису YAML |
| `static/display.js`, `static/theme.js` | Локальні налаштування LCD і теми |
| `static/style.css`, `static/theme.css`, `static/tape.css`, `static/operator.css` | Базовий layout, матеріали, плівка, робочі поверхні й контроли; порядок каскаду важливий |
| `static/index.html`, `static/manifest.webmanifest`, `static/icon*`, `static/sw.js` | Оболонка, PWA-метадані та іконки, кеш статичних файлів без API |
| `tools/dev_fixture.py`, `.dev/` | Створення й зберігання локальної синтетичної інсталяції; `.dev/` не входить у Git |
| `test_*.py`, `test_*.cjs`, `Makefile`, `.github/workflows/checks.yml` | Ізольовані регресії, команди перевірки, CI на Linux/macOS |
| `requirements.txt`, `examples/`, `deploy/` | Залежність Python, переносні приклади конфігурації та системних служб |
| `mac-preview.py` | Необов’язковий SSH-проксі та передавання лімітів CodexBar |
| `integrations/opencode-free` | Самостійний міст і розширення OMP, зі своєю ліцензією та тестами |

`index.html` підключає CSS у порядку `style.css → theme.css → tape.css → operator.css`. Останній файл уточнює попередні шари; не додавайте новий шар лише для обходу наявного каскаду. Основні container queries прив’язані до контейнера `forge`, тому ширина робочої поверхні важлива поряд із шириною viewport. Після зміни каскаду перевіряйте обчислені стилі та фактичний вигляд у двох темах і на потрібних розмірах.

## Проєкти й API

Для кожного запису конфігурації створюється власний `Forge`: проєкт, agent, стан, режимні метадані, статистика. `?project=id` вибирає об’єкт для конкретного запиту. Глобального змінного «активного проєкту» на сервері немає. Перший проєкт обслуговує старі URL без параметра.

Доступ, адміністративний токен і CSRF спільні для інсталяції одного власника. Проєкти зі спільним agent поділяють блокування запису реєстру й метадані провайдерів. `state/registries/<hash agent path>/providers.json` — їхнє єдине джерело; копія в проєктному `state.json` зберігається для сумісності. При першій міграції неоднозначні старі метадані з різними строками дії блокують запуск, а не вибираються за порядком проєктів. Це не багатокористувацькі дозволи. Сервер не приймає шляхи до файлів від браузера.

Читання: `GET /api/state`. Запис: `POST /api/profile-preview`, `/api/profile`, `/api/profile-action`, `/api/free-pools`, `/api/provider`, `/api/favorites`, `/api/refresh`. POST потребує JSON, CSRF і доступу до інсталяції. Відповіді каталогу містять лише дозволені поля моделей; ключі не передаються.

## Збереження

Конфігурація OMP зовнішня: `.omp/config.yml` і `.omp/presets/*.yml`. Standard — база; UI редагує об’єднані профілі, сервер записує мінімальні перевизначення та лишає інші поля незмінними. Дозволені лише підтримувані шляхи полів. Назви ролей і агентів беруться з конфігурації.

Копіювання й перейменування нормалізують лише нове ім’я: обрізають пробіли по краях, переводять у нижній регістр і замінюють внутрішні пробіли дефісами. Далі діє нативне правило ASCII ID до 64 символів. Відповідь повертає канонічне `name`, яке UI використовує для вибору профілю, чернетки й Undo. Колізії відхиляються без перезапису. Пошук наявного файла лишається строгим; Standard не можна перейменувати чи видалити.

Послідовність: валідація → порівняння ревізії → резервна копія → тимчасовий файл → flush/fsync → атомарна заміна. Ревізія враховує базу, preset і режимні метадані. Застарілий запис повертає 409. Symlink замість конфігурації не підтримується. Зовнішній редактор, що ігнорує блокування, теоретично може записати файл у короткому проміжку між останньою перевіркою й заміною; абсолютної міжпроцесної гарантії немає.

`profile-modes.json` зберігає логічний профіль, налаштування DeepSeek, пули й застосовану проєкцію. `profile-mode-transaction.json` забезпечує відновлення багатофайлових операцій. Зовнішні розбіжності блокують запис. Preview прив’язаний до конкретних змін і каталогу: сервер не підміняє рішення непомітно під час Save.

`mana-pool/free-good` і `mana-pool/free-fast` існують лише в логічних метаданих. Компілятор розгортає їх у native маршрути для OMP. Збереження пулів перевіряє всі залежні профілі перед записом. Ліміт — 30 CUTS у пулі; розгорнуті ланцюжки також перевіряються.

## Браузер

`original` — останній відомий серверний стан, `profiles` — робочі значення профілів. Редагування змінює чернетку; Save надсилає зміни з її ревізією. Session storage тримає незбережені значення та вихідні ревізії цієї вкладки. Undo/Redo має обмежену локальну історію й не є серверним журналом. FREE-пули мають окремі чернетку, ревізію та Undo/Redo.

Чернетки й останній вигляд мають простір імен за канонічним шляхом проєкту. Навігація між проєктами створює новий контекст сторінки. Застарілі відповіді не змінюють новий проєкт. Теми, налаштування LCD і висота колекції — спільні в цьому браузері. Legacy-ключі `forge` збережені для сумісності; міграція старих чернеток дозволяється явно для одного проєкту.

Жест попередньо показує результат і фіксує одну дію при завершенні. Обробники ручок, перенесення CUT із колекції та зміни висоти лотка скасовують жест при Escape, pointer cancel/lost capture або втраті фокуса вікном; скасування resize повертає початкову висоту. Синтетичний клік після drag не запускає другу дію. Перетягування всередині доріжки переставляє CUT, між доріжками — копіює його зі thinking. Точний маршрут, уже наявний у цільовому ланцюжку, переміщується без дублювання. Семантика місць вставки й заміни описана у [DESIGN](DESIGN.md).

Ререндер зберігає фокус, виділення у формах і прокручування; фонове опитування пропускається під час активного введення, жесту, picker, модального вікна чи збереження. Відповідь preview не змінює геометрію монтажу й не перезапускає появу відкритої панелі. Анімації реагують на зміну чернетки чи контексту, не на звичайний знімок квот, і враховують reduced motion. Service worker кешує лише оболонку; `/api/` ніколи не кешується. Статичний кеш не надає офлайн-доступу до приватного стану.

Пошук оновлює лише результати, зберігаючи активний input. Перевірка взаємодії повторюється після фонової відповіді; незавершений запис і застаріла відповідь не можуть повернути попередній стан. Для preview діє вужча межа: завершений вибір Thinking і меню перестановки мають отримувати готову проєкцію без закриття. Повторна дія з індексом CUT очікує актуальної проєкції. Кеш похідних обчислень існує лише в межах одного render, без окремого глобального механізму інвалідації.

## Межі інтеграцій

OMP викликається для каталогу, лімітів і агрегатів, не для inference. Agent-каталог задається через `PI_CODING_AGENT_DIR`. Панель не управляє життєвим циклом OMP-воркерів. OpenCode Free працює в окремому процесі та має власний стан; його відсутність не зупиняє UI. Автоматичний supervisor — системна служба користувача, а не агент чи запущена сесія Codex.
