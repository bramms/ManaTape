# Конфігурація

Є три незалежні частини: код Mana Tape, приватна конфігурація інсталяції та зовнішні проєкти OMP. Репозиторій не повинен містити особистих конфігурацій, ключів, реєстрів, журналів або резервних копій.

## Інсталяція

Стартуйте з [examples/installation.yml](../examples/installation.yml). `--config` приймає YAML. Відносні шляхи — від каталогу YAML; `~` і змінні оточення розгортаються. Після зміни списку проєктів перезапустіть лише Mana Tape.

| Поле | Значення |
|---|---|
| `projects` | Непорожній список проєктів |
| `projects[].id` | Унікальний сталий ID: малі латинські літери, цифри, `_`, `-`; до 64 символів |
| `projects[].name` | Назва в селекторі; може бути українською |
| `projects[].path` | Каталог із `.omp/config.yml` |
| `agent` | Реєстр OMP; типово `~/.omp/agent` |
| `projects[].agent` | Інший реєстр для цього проєкту; необов’язково |
| `state` | Корінь приватного стану; типово `~/.local/share/mana-tape` |
| `projects[].state` | Явний каталог стану для міграції; інакше `state/id` |
| `omp` | Назва виконуваного файла з PATH або абсолютний шлях |
| `port` | Локальний порт, типово 19421; `--port` має пріоритет |
| `origin`, `owner` | Приватна HTTPS-адреса та точна Tailscale-ідентичність власника |
| `noRefresh` | Вимкнути фонове оновлення, типово false; також `--no-refresh` |
| `demo` | Позначити тестову інсталяцію; саме по собі не ізолює файли |
| `projects[].legacyDrafts` | Одноразово перенести старі браузерні чернетки у простір цього проєкту; лише для міграції старої інсталяції |

Один каталог проєкту або стану не можна використати двічі. Перший проєкт — типовий для URL без `?project=id`. Запити з невідомим ID відхиляються. ID не є дозволом доступу: усі налаштовані проєкти доступні власнику інсталяції.

Сумісний запуск одного проєкту:

```sh
.venv/bin/python server.py --project ~/Projects/my-project --agent ~/.omp/agent --state ~/.local/share/mana-tape/main
```

## Ролі й агенти

Панель читає ролі з `modelRoles` обраного профілю, включно з ролями, доданими лише в preset. Набір не зашитий у програму. Нові ролі й агенти додавайте у YAML OMP; панель редагує їхні маршрути. Не потрібно заводити `task`, `smol`, `sonic` або будь-які інші обов’язкові ролі заради Mana Tape.

Секція «Агенти» читає `task.agentModelOverrides`. Значення з одним `@role` та власні списки мають різну поведінку успадкування резервів; приклади й точні правила наведені у [роботі з агентами](USAGE.md#агенти).

```yaml
modelRoles:
  researcher: my-provider/model-a
  editor: my-provider/model-b
retry:
  fallbackChains:
    researcher: [my-provider/model-b]
task:
  agentModelOverrides:
    research-team: ['@researcher', my-provider/model-b]
```

Назви для інтерфейсу задаються без зміни native ID:

```yaml
projects:
  - id: writing
    name: Тексти
    path: ~/Projects/writing
    ui:
      roleLabels:
        researcher: Дослідження
        editor: Редактор
      localProviders: [my-local]
      visionRoles: [image-reviewer]
```

Локальні провайдери з discovery `ollama`, `llama.cpp`, `lm-studio` визначаються автоматично. Інші позначаються через `localProviders`; локальна адреса проксі сама по собі не означає локальну модель.

Для власних ролей можна задати `ui.benchmarkWeights` (LiveBench) і `ui.benchmarkWeightsAA` (Artificial Analysis). Формат: словник `роль: {назва_метрики: вага}`. Кожне поле повністю замінює відповідну типову таблицю. Без налаштування оцінки є лише для `default`, `task`, `smol`; іншим ролям доступні сирі результати без вигаданого бала. Наприклад: `benchmarkWeights: {researcher: {Reasoning: 0.7, IF: 0.3}}`.

## Межі спільних даних

Профілі, FREE-пули, обрані CUTS, чернетки, журнал режимів і резервні копії належать конкретному проєкту. FREE-пули спільні для його доріжок і профілів, а не для всіх незалежних проєктів.

Проєкти з однаковим `agent` використовують спільний `models.yml`, облікові записи, каталог OMP та його статистику. Зміна підключення провайдера впливає на весь цей реєстр. Назви й терміни дії провайдерів спільні для реєстру та зберігаються в `state/registries/<ідентифікатор>/providers.json`. Поновлення з будь-якого проєкту оновлює спільний строк. Видалення й автоматичне завершення строку враховують використання в усіх налаштованих проєктах цього реєстру. Проєкти поза списком інсталяції не перевіряються. Статистика показує агрегати реєстру, а не приписує всі виклики обраному проєкту. Для повної ізоляції задайте різні agent-каталоги.

Застосунок передає `PI_CODING_AGENT_DIR` у дочірні команди OMP. Проєктні розширення під час оновлення каталогу не завантажуються. Встановлений `extensions/opencode-free.js` підключається явно; це єдина спеціальна необов’язкова інтеграція каталогу.

`ui.visionRoles` задає точні ID ролей, яким потрібні зображення при замінах і розгортанні пулів; типово лише native-роль `vision`. Назви на кшталт `image-reviewer` не мають прихованого значення. `ui.providerLabels` та `ui.providerCodes` дозволяють локальні підписи й короткі коди провайдерів.
