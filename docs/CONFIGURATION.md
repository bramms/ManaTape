# Конфігурація

Є три незалежні частини: код Mana Tape, приватна конфігурація інсталяції та зовнішні проєкти OMP. Репозиторій не повинен містити особистих конфігурацій, ключів, реєстрів, журналів або резервних копій.

## Інсталяція

Інсталяційний YAML необов’язковий. Без `--config` сервер бере `~/.config/mana-tape/installation.yml`, якщо він є, інакше типові значення: каталог агента `~/.omp/agent` (`--agent`), стан `~/.local/share/mana-tape` (`--state`), глобальна область і знайдені проєкти. Приклад — [examples/installation.yml](../examples/installation.yml). Відносні шляхи — від каталогу YAML; `~` і змінні оточення розгортаються. Після зміни YAML перезапустіть лише Mana Tape.

| Поле | Значення |
|---|---|
| `projects` | Необов’язковий список явних областей; якщо ключ є, список не порожній |
| `projects[].id` | Унікальний сталий ID: малі латинські літери, цифри, `_`, `-`; до 64 символів |
| `projects[].name` | Назва в селекторі; може бути українською |
| `projects[].path` | Каталог із `.omp/config.yml`; не потрібен для `scope: user` |
| `projects[].scope` | `project` (типово) або `user` — глобальна область цього каталогу агента (`<agent>/config.yml`): вона зберігає свій `id`, назву, `ui` і каталог стану. Одна на каталог агента |
| `agent` | Реєстр OMP; типово `~/.omp/agent` |
| `projects[].agent` | Інший реєстр для цього проєкту; необов’язково |
| `state` | Корінь приватного стану; типово `~/.local/share/mana-tape` |
| `projects[].state` | Явний каталог стану для міграції; інакше індекс `state/scopes.json` або `state/<id>` |
| `ui` | Налаштування інтерфейсу глобальної області; проєкти їх успадковують |
| `projectRoots` | Каталоги, чиї безпосередні підкаталоги з `.omp/config.yml` стають областями |
| `discover` | `false` вимикає пошук проєктів в історії сесій OMP; типово `true` |
| `omp` | Назва виконуваного файла з PATH або абсолютний шлях |
| `port` | Локальний порт, типово 19421; `--port` має пріоритет |
| `origin`, `owner` | Приватна HTTPS-адреса та точна Tailscale-ідентичність власника |
| `noRefresh` | Вимкнути фонове оновлення, типово false; також `--no-refresh` |
| `demo` | Позначити тестову інсталяцію; саме по собі не ізолює файли |
| `projects[].legacyDrafts` | Одноразово перенести старі браузерні чернетки у простір цього проєкту; лише для міграції старої інсталяції |

Один каталог проєкту або стану не можна використати двічі. Перший явний запис — типовий для URL без `?project=id`; без явних записів — глобальна область. `?project=global` завжди веде до глобальної області типового агента. Запити з невідомим ID відхиляються. ID не є дозволом доступу: усі області доступні власнику інсталяції.

Сумісний запуск одного проєкту без областей і пошуку:

```sh
.venv/bin/python server.py --project ~/Projects/my-project --agent ~/.omp/agent --state ~/.local/share/mana-tape/main
```

## Області: глобальна й проєкти

OMP 18.9 читає налаштування шарами: глобальний `<agent>/config.yml`, потім `<cwd>/.omp/config.yml` каталогу, де запущено сесію (лише сам `cwd`, без пошуку в батьківських каталогах і не в домашньому каталозі), потім `--config`/`PI_CONFIG_FILES`. Мапи зливаються за ключами (`modelRoles` — за ролями, `retry.fallbackChains` — за ключами, `task.agentModelOverrides` — за агентами), а списки, рядки й `null` замінюють значення цілком (`disabledProviders` — один список). `role: null` у проєкті не скасовує глобальну роль: OMP її просто пропускає.

Mana Tape показує ті самі шари. **Глобальна область** є завжди (одна на каталог агента); її файл може ще не існувати й з’являється з першим явним збереженням. **Проєкт** — накладка: панель показує успадковані значення й джерело кожного (`проєкт` / `глобально` / типово OMP), записує в проєкт лише відмінності й уміє «скинути до глобального» (прибрати значення з проєкту) та «перенести в глобальні» (одним журналом записати значення в глобальний файл і прибрати з проєкту). `modelRoleStorage: project` в OMP означає, що вибір моделі в самому OMP пише ролі в `.omp/config.yml` проєкту (переписуючи файл без коментарів); інакше — у глобальний файл. Mana Tape моделює лише `.omp/config.yml`; `.omp/settings.json`, налаштування інших інструментів і `--config` не показуються. Резервні ланцюжки з ключем-моделлю (`retry.fallbackChains["provider/model"]`) OMP обирає раніше за ланцюжок ролі; панель лише називає такі ключі.

Mana Tape керує у файлі області лише `modelRoles`, `retry.fallbackChains`, `task.agentModelOverrides`, `disabledProviders` і `modelPresets`. Решту ключів (`theme`, `defaultThinkingLevel`, `modelRoleStorage`, інші частини `retry` і `task`, коментарі) пише OMP чи власник: зміна лише в них поза панеллю — не конфлікт, і наступний запис панелі її зберігає. Конфліктом («Прийняти файл») лишається лише зміна ключів, якими керує панель; повідомлення називає область і файл. Ревізія проєкту стежить лише за тією частиною глобального файлу, від якої залежить проєкт, тож OMP, що переписує глобальну тему чи thinking, не скидає чернеток проєктів.

Проєкт компілюється проти поточного глобального файлу, каталогу й пулів. Якщо через це запис змінить у файлі щось, чого дія не просила (наприклад, перший запис у проєкті в режимі DeepSeek OFF перевизначає роль, яку глобальний файл тим часом поставив на платний DeepSeek), сервер нічого не пише й показує ці рядки; запис іде лише з підтвердженням саме того, що показано (`409 derived` і `token` → `confirm`). Дії з підтвердженням у шухляді (підняти в глобальне, застосувати котушку) показують перегляд усіх змін файлів заздалегідь.

Глобальний `config.yml`, що є символьним посиланням (наприклад, із репозиторію dotfiles), панель читає через посилання, але не записує: глобальна область стає лише для перегляду, а проєкти працюють, як завжди (дії, що пишуть глобальний файл, відмовляють із кодом `symlink`).

Проєкти панель знаходить сама: із заголовків файлів сесій OMP (`<agent>/sessions/*/*.jsonl`, поле `cwd`; назви тек не розшифровуються) і з `projectRoots`. Каталог із `.omp/config.yml` стає областю; каталог без нього — кандидатом. Файл `.omp/config.yml` для кандидата створюється лише явною дією «Налаштувати» за ідентифікатором, який видав сервер; браузер шляхів не надсилає. Пошук повторюється не частіше разу на хвилину.

Стан областей ключується автоматично: `state/scopes.json` зіставляє шлях області з її каталогом стану. Явні записи мають пріоритет; каталоги стану старших інсталяцій зіставляються за шляхами в їхніх резервних копіях (`state.json` → `backups`), тож нічого не переноситься й не перейменовується.

## Котушки

Котушка — нативний пресет OMP: запис `modelPresets.<назва>` у файлі області (`.omp/config.yml` проєкту або глобальний `config.yml`). OMP зберігає в пресеті лише моделі ролей і `defaultThinkingLevel`; `/modelpreset switch` (або «Застосувати» в панелі) записує ці ролі туди, де OMP зберігає ролі (`modelRoleStorage`), а рівень thinking — у глобальний файл. «Застосувати» пише саме записані маршрути котушки (блок FREE-пулу — його перший CUT, котушка в режимі OFF — свої заміни) і не додає й не змінює резервних ланцюжків; якщо файл області при цьому змінився б ще в чомусь, це показано й потребує підтвердження. Котушку з платним DeepSeek не можна застосувати в область, чий Standard у режимі DeepSeek OFF: її режим одразу замінив би ці ролі, тож панель відмовляє (`deepseek-mode`) і пропонує перемкнути котушку або область. Активну котушку OMP не запам’ятовує: активна та, чиї ролі точно збігаються з ролями, що діють. Пресет проєкту затуляє глобальний з тією самою назвою. Назва починається з латинської літери.

Старі котушки `.omp/presets/*.yml` OMP читав лише через `--config`. Панель показує їх, доки власник не перенесе кожну: план перенесення називає все, чого нативний пресет не несе (резервні ланцюжки, агенти, провайдери), і пропонує три способи — лише ролі, ролі з ланцюжком із ключем-моделлю там, де це точно, або архів без пресета. Старий файл і його запис режиму спершу йдуть у резервні копії стану.

## Ролі й агенти

Панель завжди показує штатні ролі OMP 18.6.1: `default`, `smol`, `slow`, `vision`, `plan`, `commit`, `tiny`, `memory`, `task`, `advisor`, `image`, `web`, `speech`, `dictation`, `judge`. Додаткові ролі читаються з `modelRoles` обраного профілю, включно з ролями, доданими лише в preset. П’ять штатних агентів (`scout`, `reviewer`, `security-reviewer`, `task`, `sonic`) також доступні без записів `task.agentModelOverrides`. Власних агентів OMP панель знаходить сама: Markdown-файли з frontmatter (`name`, `description`, за потреби `model`) у `<проєкт>/.omp/agents/` та `<каталог агента OMP>/agents/` (зазвичай `~/.omp/agent/agents/`). Якщо імена збігаються, проєктний агент важливіший за користувацький, а той — за штатного. Файли панель лише читає; без коректних `name` і `description` файл пропускається. Власні ролі додавайте у YAML OMP; панель редагує їхні маршрути. Для штатних ролей додаткові записи чи налаштування інсталяції не потрібні. Вибір моделі й повернення до типового вибору описані у [роботі з панеллю](USAGE.md#ролі).

Секція «Агенти» читає `task.agentModelOverrides`. Значення з одним `@role` та власні списки мають різну поведінку успадкування резервів; приклади й точні правила наведені у [роботі з агентами](USAGE.md#агенти).

```yaml
modelRoles:
  researcher: my-provider/model-a
  editor: my-provider/model-b
retry:
  fallbackChains:
    researcher: [my-provider/model-b]
task:
  agentModelOverrides:
    research-team: ['@researcher', my-provider/model-b]
```

Назви для інтерфейсу задаються без зміни native ID. `ui` верхнього рівня діє для глобальної області й усіх проєктів; `ui` запису проєкту доповнює або замінює окремі ключі (мапи зливаються, списки замінюються):

```yaml
ui:
  providerLabels:
    my-local: LOCAL
projects:
  - id: writing
    name: Тексти
    path: ~/Projects/writing
    ui:
      roleLabels:
        researcher: Дослідження
        editor: Редактор
      localProviders: [my-local]
      visionRoles: [image-reviewer]
```

Локальні провайдери з discovery `ollama`, `llama.cpp`, `lm-studio` визначаються автоматично. Інші позначаються через `localProviders`; локальна адреса проксі сама по собі не означає локальну модель.

Для власних ролей можна задати `ui.benchmarkWeights` (LiveBench) і `ui.benchmarkWeightsAA` (Artificial Analysis). Формат: словник `роль: {назва_метрики: вага}`. Кожне поле повністю замінює відповідну типову таблицю. Без налаштування оцінки є лише для `default`, `task`, `smol`; іншим ролям доступні сирі результати без вигаданого бала. Наприклад: `benchmarkWeights: {researcher: {Reasoning: 0.7, IF: 0.3}}`.

## Межі спільних даних

Профілі, котушки, обрані CUTS, чернетки, журнал режимів і резервні копії належать конкретній області. FREE-пули спільні для всієї машини — для всіх областей одного каталогу агента: `state/registries/<ідентифікатор>/pools.json`. Під час першого запуску сюди переносяться пули старих проєктів; якщо вони різні, панель нічого не обирає сама й просить власника вибрати джерело. Старі записи пулів у `profile-modes.json` лишаються на місці.

Проєкти з однаковим `agent` використовують спільний `models.yml`, облікові записи, каталог OMP та його статистику. Оновлення каталогу (`omp models refresh`), перевірку строків провайдерів і телеметрію (`omp usage`, `omp stats`, тести моделей) виконує одна область на каталог агента — перший явний запис інсталяції, інакше глобальна; інші області, також знайдені пізніше, показують її каталог і телеметрію. `models.yml` має бути звичайним файлом: через символьне посилання (наприклад, з репозиторію dotfiles) панель лише читає провайдерів, а збереження відхиляє, щоб не замінити посилання копією. Зміна підключення провайдера впливає на весь цей реєстр. Назви й терміни дії провайдерів спільні для реєстру та зберігаються в `state/registries/<ідентифікатор>/providers.json`. Поновлення з будь-якого проєкту оновлює спільний строк. Видалення й автоматичне завершення строку враховують використання в усіх налаштованих проєктах цього реєстру, включно з котушками (`modelPresets`) глобальної області й проєктів. Проєкти поза списком інсталяції не перевіряються. Статистика показує агрегати реєстру, а не приписує всі виклики обраному проєкту. Для повної ізоляції задайте різні agent-каталоги.

Застосунок передає `PI_CODING_AGENT_DIR` у дочірні команди OMP. Під час оновлення каталогу пошук розширень вимкнено, тож проєктні розширення не виконуються. Розширення, встановлені в каталозі агента OMP, підключаються явно, у порядку назв: файли `*.js` і `*.ts` безпосередньо в `<agent>/extensions/` (ті розширення, які OMP знаходить там сам) — звичайні або символьні посилання на звичайний файл. Приховані файли, підкаталоги й зламані посилання пропускаються; деморежим розширень не підключає.

`ui.visionRoles` задає точні ID ролей, яким потрібні зображення при замінах і розгортанні пулів; типово лише native-роль `vision`. Назви на кшталт `image-reviewer` не мають прихованого значення. `ui.providerLabels` та `ui.providerCodes` дозволяють локальні підписи й короткі коди провайдерів.
