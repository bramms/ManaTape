# Експлуатація

## Локальний запуск

Встановлення описане в README. Секрети залишайте в agent-каталозі OMP або зовнішніх файлах, на які посилається його `models.yml`. Каталог стану Mana Tape містить `state.json`, `profile-modes.json`, `insights.json`, `local-token`, резервні копії та за потреби журнал незавершеної транзакції. Не видаляйте його при оновленні коду.

Прямий запуск у терміналі працює на Linux/macOS. Він завершується разом із процесом. Для автозапуску використовуйте системний менеджер служб.

## Linux: systemd користувача

Приклад у `deploy/mana-tape.service.example`. Він передбачає код у `~/Apps/ManaTape` та конфігурацію у `~/.config/mana-tape/installation.yml`; змініть шляхи під свою інсталяцію. Задайте абсолютний `omp` у YAML, якщо служба не має вашого інтерактивного PATH.

```sh
mkdir -p ~/.config/systemd/user
cp deploy/mana-tape.service.example ~/.config/systemd/user/mana-tape.service
systemctl --user daemon-reload
systemctl --user enable --now mana-tape.service
systemctl --user status mana-tape.service
```

`Restart=on-failure` піднімає процес після збою. Автозапуск без входу користувача потребує налаштованого linger (`loginctl enable-linger USER`, якщо дозволено адміністратором). Це окреме системне налаштування, не властивість застосунку.

## macOS: launchd

У `deploy/local.manatape.plist.example` замініть `/ABSOLUTE/PATH` і `YOUR_USER`. Використовуйте абсолютні шляхи: launchd не розгортає `~` і не читає інтерактивний PATH. Збережіть як `~/Library/LaunchAgents/local.manatape.plist`.

```sh
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/local.manatape.plist
launchctl kickstart "gui/$(id -u)/local.manatape"
```

Це служба поточного користувача після входу; `KeepAlive` відновлює процес після збою. Зупинка: `launchctl bootout "gui/$(id -u)" ~/Library/LaunchAgents/local.manatape.plist`.

## SSH з іншого комп’ютера

На сервері Mana Tape має працювати окремо. На клієнті потрібні Python 3.11+ та вже налаштований SSH-ключ/host; скрипт не встановлює ключів і не змінює SSH-конфігурацію.

Скопіюйте `examples/ssh.json` у `~/.config/mana-tape/ssh.json`, вкажіть SSH host та абсолютний каталог стану **першого** проєкту. Запуск із каталогу коду:

```sh
python3 mac-preview.py
```

Попри історичну назву файл підтримує також Linux. Він створює SSH-тунель, слухає локальний 19423 і відкриває браузер. `--no-open` вимикає відкриття. Параметри `--host`, `--state`, `--remote-port`, `--port` перевизначають JSON. Адміністративний токен читається через SSH й залишається лише в пам’яті проксі. Після перезапуску сервера перезапустіть проксі, щоб отримати новий токен. Закриття launcher зупиняє тунель, але не сервер. Проксі тримає кілька keep-alive з’єднань через тунель, передає стиснення й валідатори (`Accept-Encoding`, `If-None-Match`, `ETag`, `Content-Encoding`, `Cache-Control`) і передає відповіді потоком. Будь-яка помилка з’єднання закриває весь пул (після збою тунелю всі збережені з’єднання застарілі), і GET повторюється один раз на новому з’єднанні, тож панель повертається з «офлайн» уже наступним опитуванням; POST, тайм-аут і відмова нового з’єднання (тунель лежить) не повторюються. Якщо launcher запускається з копії поза репозиторієм, після оновлення коду скопіюйте `mac-preview.py` заново.

Для CommandCode на macOS за наявності CodexBar можна ввімкнути `commandcode: true` у SSH JSON або `--commandcode`. Проксі раз на п’ять хвилин передає лише нормалізований звіт лімітів у вказаний каталог стану. Cookies і первинний звіт CLI не передаються. Без цієї опції CodexBar не викликається.

## Приватний HTTPS

Налаштуйте Tailscale Serve до loopback-порту, точний `origin` на кшталт `https://your-host.your-tailnet.ts.net` та `owner` з Tailscale-ідентичністю. Доступ перевіряється за заголовком довіреного проксі. На Linux `tailscaled` має працювати від root або від того самого користувача, що й Mana Tape: заголовки від з’єднань інших облікових записів відхиляються (межі — у [безпеці](../SECURITY.md)). Прямий браузерний доступ до loopback при заданому origin відхиляється; SSH launcher додає приватний токен. HTTPS також дозволяє встановлення панелі як PWA на телефоні.

## Оновлення й відновлення

1. Збережіть потрібні чернетки. Зробіть приватну резервну копію YAML інсталяції, всього кореня `state` (включно з `registries/`), явних `projects[].state` та зовнішніх `.omp` конфігурацій. Ключі й резервні копії не додавайте до Git.
2. Отримайте новий код, встановіть залежності, виконайте `make test check` на fixtures.
3. Перезапустіть **лише Mana Tape** і клієнтський SSH launcher. OMP та його воркери перезапускати не потрібно.
4. Перевірте читання профілів і каталогу. Не тестуйте Save на справжньому профілі без наміру змінити його.

Резервні копії у `state/backups` містять попередні версії; для прямих записів зберігаються останні 20 копій із точно тим самим ім’ям файла (`<час>-config.yml` не зачіпає `<час>-x-config.yml`). Копія, на яку вказує «Відновити», а також копії видалених (`-deleted-`, `-deleted-preset-`), забутих (`-forgotten-`) і перенесених (`-migrated-`) профілів та збережені журнали не очищаються. Режимні транзакції створюють додаткові копії без автоматичного очищення; враховуйте їх при контролі дискового простору. UI-відновлення працює з актуальною ревізією. Для ручного відкату спочатку зупиніть Mana Tape, відновлюйте узгоджену копію native YAML **разом** із режимними метаданими, потім запускайте панель. Не видаляйте журнал транзакції навмання — він потрібен для відновлення після перерваного запису. Записи, що змінюють кілька областей (пули, «перенести в глобальні», «Застосувати» котушку), мають спільний журнал `state/registries/<ідентифікатор>/transaction.json`; там само лежать спільні `pools.json` і `providers.json`, а `state/scopes.json` зіставляє області з їхніми каталогами стану.

Якщо перерваний запис не вдалося відкотити (немає місця, немає прав або файл змінено іззовні), Mana Tape не падає й не перезапускається по колу: панель читається, `/api/state` показує `modeRecovery`, а кожен запис відхиляється з кодом `mode-recovery`. Після звільнення місця наступна дія запису завершить відновлення сама. Файл, змінений іззовні під час запису, перевірте й прийміть дією `adopt` у `/api/profile-action`; файли Mana Tape при цьому вже повернуто до попереднього стану.

Для перенесення існуючої інсталяції вкажіть старий каталог через `projects[].state`, а зовнішній проєкт через `path`. Тоді налаштування не потрібно копіювати. Каталоги стану старших версій без явного запису Mana Tape зіставляє з проєктами сам — за шляхами в їхніх резервних копіях; нічого не переносить і не перейменовує. Якщо переміщуєте каталог стану, перенесіть усі файли разом і перевірте абсолютні посилання на ключі й backups. Старі шляхи можна зберегти символічними посиланнями. Увімкніть `legacyDrafts` тільки для проєкту, якому належали старі браузерні чернетки.

## Діагностика

- Немає з’єднання: перевірте процес, порт, SSH host; після restart сервера перезапустіть launcher.
- 403: Host/Origin/owner/token/CSRF не відповідають налаштуванню. Не вимикайте перевірки; перечитайте конфігурацію й відкрийте належну адресу.
- 409: зовнішня зміна YAML або метаданих. Чернетка лишається у вкладці; узгодьте її з поточним файлом. Код `mode-conflict` означає, що файл із режимом змінено поза панеллю: прийміть файл (`adopt`) або відновіть попередню версію. Код `symlink` — `models.yml` є символьним посиланням; замініть його звичайним файлом або змінюйте ціль вручну.
- `mode-recovery` (503 або 409): перерваний запис не вдалося відкотити. 503 — найчастіше брак місця чи прав: виправте й повторіть дію. 409 — файл змінено іззовні під час запису: перевірте його й прийміть (`adopt`).
- Збої сервера записуються у stderr як тип винятку, errno й місце в коді, без вмісту запитів: `journalctl --user -u mana-tape` для systemd; для launchd задайте `StandardErrorPath` у plist, інакше stderr не зберігається.
- Старий каталог: перевірте шлях `omp`, agent-каталог і доступність провайдера. Попередній знімок навмисно не видаляється при збої.
- OpenCode Free не працює: перевіряйте окрему службу моста та `bridge.py doctor`; основна панель і платні підключення незалежні.
