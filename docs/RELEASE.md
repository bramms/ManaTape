# Підготовка публічного випуску

Перший публічний випуск — **[0.1.0](https://github.com/bramms/ManaTape/releases/tag/v0.1.0)**. [Нотатки версії](../CHANGELOG.md) описують його склад; цей документ визначає перевірки перед публікацією. Наявність документа чи тегу сама по собі не підтверджує проходження перевірок.

Перед відкриттям:

1. Перевірити наявність [MIT-ліцензії основного проєкту](../LICENSE), окремої MIT-ліцензії OpenCode Free та атрибуції джерел.
2. Перевірити всю історію Git і матеріали GitHub, а не лише робочу папку: секрети, особисті адреси, конфігурації OMP, історичні журнали та скріншоти.
3. Пройти чисте встановлення на Linux/macOS, offline-тести й перевірку двох незалежних проєктів.
4. Перевірити приватний доступ і резервне відновлення на тестовій інсталяції; не використовувати справжні проєкти як fixture.
5. Перевірити документацію щодо сумісної версії OMP і поточного стану необов’язкового OpenCode Free. Не обіцяти незмінний безкоштовний каталог.
6. Зафіксувати перевірений commit і результати у [VALIDATION](VALIDATION.md), завершити нотатки версії, перевірити спосіб приватного повідомлення про вразливості з [SECURITY](../SECURITY.md).
7. Після завершення перевірок і дозволу власника відкрити репозиторій, створити тег `v0.1.0` на перевіреному commit і GitHub Release з нотатками цієї версії. Перевірити, що репозиторій, тег, ліцензія й документація доступні без авторизації. Перехід до публічного коду не означає публічний доступ до особистої інсталяції Mana Tape.

Для наступних версій повторюються перевірки змінених компонентів і приватності нових матеріалів; повний огляд доступної історії обов’язковий перед першим відкриттям. Чистий робочий каталог не доводить відсутності приватних даних у старих комітах, тегах, release assets чи матеріалах GitHub.
