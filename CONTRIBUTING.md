# Розробка

Python 3.11+, Node.js 22+, Git. Немає frontend-збірки чи npm-залежностей.

Почніть із [AGENTS](AGENTS.md): там спільний маршрут для людини й будь-якого AI-агента, порядок читання та обов’язкові обмеження. [Карта документації](docs/index.md) веде до потрібної теми, [MAINTENANCE](docs/MAINTENANCE.md) описує підтримку й оновлення канону. Інструкції не залежать від конкретної моделі чи середовища агента.

```sh
make install
make test check
make demo
# Або насичений пульт для візуального рев’ю
make demo-showcase
```

`make demo` створює лише синтетичні файли в `.dev/` і запускає порт 19424 без фонового доступу до OMP. Не підміняйте demo реальним agent-каталогом. Зміни backend потребують перезапуску демосервера, JavaScript — перезавантаження власної тестової вкладки.

`test_projects.py` перевіряє адресацію записів між двома проєктами, невідомі ID, CSRF, спільне блокування реєстру та довільні агенти. Решта тестів покриває режими, транзакції, FREE-пули, ревізії, evidence, Undo та чисту логіку інтерфейсу. GitHub Actions запускає offline-перевірки на Ubuntu і macOS.

Для OpenCode Free:

```sh
cd integrations/opencode-free
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/extension.test.mjs
```

Не надсилайте справжні ключі, тарифи особистого рахунку, статистику чи шляхи приватних проєктів у issue/PR. Мінімальний звіт: ОС, версії Python/OMP, кроки, очікувана й фактична поведінка, синтетичний приклад. Опис PR має пояснювати проблему, зміну й перевірки. Мову документації та інтерфейсу зберігаємо українською; протокольні ID й сторонні ліцензії не перекладаємо.

Пояснюйте зміни для людини, яка вперше встановлює або використовує Mana Tape. Зміна дії в панелі має бути відображена в USAGE, параметра — у CONFIGURATION, запуску чи відновлення — в OPERATIONS. Принципи інтерфейсу й гарантії реалізації підтримуйте відповідно в DESIGN та ARCHITECTURE. Посилайтеся на канонічне пояснення, не копіюючи його в кілька документів.

Для змін лише тексту перевірте точність інструкцій, відносні посилання та узгодженість термінів; запуск тестів коду сам по собі не перевіряє документацію. У звіті відрізняйте виконані тести, огляд коду, браузерні перевірки та людське приймання. Не позначайте перевірку агента як людську й не переносіть результати старого зрізу на нову версію.
